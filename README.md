# LALR1parser
[![Parser Tests](https://github.com/Koutya418/LALR1parser/actions/workflows/test.yml/badge.svg)](https://github.com/Koutya418/LALR1parser/actions/workflows/test.yml)
LR(0)からの先読み記号の伝搬によるアルゴリズムで実装したLALR1パーサージェネレーターです。  

## 背景
このプロジェクトは将来的に自作CPU上で動かす自作コンパイラの作成の為の一環として、アルゴリズムの理解の為に実装したものです。  
上記の目的から比較的解析範囲が広い事、計算資源が制約された環境での実行を求められる為、状態数が多いLR(1)からの統合ではなくLR(0)からの伝搬による実装でのLALR1を採用しました。  

## 使用方法
src/Parser.pyにあるparse関数にトークナイザーの規則、生成規則、解析したいファイルのパスを渡すと構文解析が行えます。

## 生成規則の記述について
bnf記法に近い記法を採用しています。詳細は以下の通りです。

### 記号について
- 非終端記号:<非終端記号>の様に<>で囲む。  
- 終端記号:"終端記号"の様に""で囲む。  
- トークン:字句解析の定義で定義したトークンを記述。※詳細は字句解析の記述についてを参照。

### 規則定義について
開始規則にはS'を用います。  
規則の最後にセミコロンを付けた以下の様な構文になります。  
- \<digit\> ::= "1";  
- \<digit\> ::= "1" | "2";
- \<number\> ::= \<number\> \<digit\> | \<digit\>;

### 優先順位について
以下の様な記述で優先順位を宣言できます。  
- %left "+" "-"  
- %left "*" "/"  
- %right UMINUS  

この時上から下に向けて優先順位が高くなり、同じ優先順位の際に%leftの場合は左結合、%rightの場合は右結合になります。  

また以下の様に規則に対して優先順位を適用できます。  
- \<expression\> ::= "-" \<expression\> %prec UMINUS;  

この場合 "-" \<expression\> にUMINUSの優先順位が適用されます。

## 字句解析の記述について
トークンに対してそのトークンの正規表現のパターンを記述します。
- int = "/d/d*"  
- id = "(/z|_)/w*"  

その上で生成規則で用いる場合以下の様に記述します。
- \<number\> ::= int;  

この様にした場合\<number\>はintトークンを終端記号として構文解析器が解釈を行います。

またトークンと終端記号が一致する場合、以下の様に終端記号として解釈されます。  
- \<arithmetic_operator\> ::= "+" | "-" | "*" | "/";
- operator = "+|-|*|/"  

この場合にoperatorでトークン化されたトークンはトークンではなく、終端記号として扱われます。

トークン名のskipは予約済みであり、このトークン名のトークンは構文解析時に無視されます。

## 正規表現について
- /d : 数字
- /a : 小文字のアルファベット
- /A : 大文字のアルファベット
- /z : アルファベット
- /Z : アルファベット, アンダーバー
- /w : 数字, アルファベット, アンダーバー
- ,  : スペースと改行以外を除く任意の文字
- .  : 任意の文字
- \*  : 繰り返し
- !  : 最短マッチ
- |  : OR
- () : グループ化


## 制約・注意点
### 全体
- エラー処理に関して未整備の箇所があります。  
- 正常系でのテストがメインであり、準正常系や異常系のテストは一部しか行っていません。

### 構文解析器
- Reduce/Reduce衝突に関して解決する機能が未実装な為、テーブル生成が適切に行えないケースがあります。
- Shift/Reduce衝突時のエラー表示は初期状態では無効化されています。表示する場合src/components/Lalr1.pyの55行目のprint文のコメントを外してください。

### 字句解析器
- 正規表現に関して、Pythonの文字列ではバックスラッシュがエスケープとして扱われる為独自記法が採用されています。
